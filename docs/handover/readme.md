# System Handover Documentation

This folder contains documentation for the Task Tracker system as it exists at the start of the **Group Project phase**.

Your team is inheriting an existing codebase that was developed during earlier individual project sprints. Before implementing new features, review the documents in this folder to understand the current architecture and testing strategy.

## Recommended Reading Order

To understand the system quickly, review the documents in this order:

1. **System Architecture**
   - `group_project_start_architecture.md`
   - Overview of the application layers and major components.

2. **Class Structure**
   - `group_project_start_class_diagram.md`
   - Describes how the main classes interact.

3. **Database Design**
   - `group_project_erd.md`
   - Entity-relationship diagram for the database schema.

4. **API Reference**
   - `group_project_api_reference.md`
   - Describes the existing API endpoints.

5. **Testing Strategy**
   - `group_project_test_strategy.md`
   - Explains the testing layers used in the project.

6. **Test Cases**
   - `group_project_start_test_cases.md`
   - Example tests that verify system behavior.

7. **User Journey**
   - `user_journey.md`
   - Example workflow showing how users interact with the application.

8. **Developer Setup**
   - `developer_setup.md`
   - Instructions for running the project locally.

## Goal of Sprint 1

During Sprint 1, your team should:

- understand the architecture of the system
- run the application locally
- execute the automated tests
- review the existing user stories
- select features your team will implement

This sprint simulates a **real-world development scenario where a new team inherits an existing system and must understand it before extending it.**
